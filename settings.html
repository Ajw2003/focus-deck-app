GitHub token

Focus Deck uses this token to link tasks to issues, create new issues from tasks, close/reopen a linked issue when you complete a task, and keep categories in sync as GitHub labels. Set it up once:

  1. Open Create a fine-grained token on GitHub.
  2. Under Repository access, choose All repositories — or Only select repositories and add every repo you want Focus Deck to link, create issues in, or sync labels with.
  3. Under Repository permissions, set Issues to Read and write — this one setting covers linking, creating issues, closing/reopening, and adding/removing labels (GitHub doesn't split those into separate permissions). Leave Metadata at its default Read-only (GitHub requires it on every fine-grained token).
  4. Under Account permissions, set Gists to Read and write — only needed for the cross-device sync below.
  5. Under Repository permissions, set Administration to Read and write — only needed to create new repos from Focus Deck; everything else works without it.
  6. Generate the token and paste it below. It's stored only in this browser and sent only to api.github.com.

Already have a token? Edit its permissions on that same token on GitHub — no need to paste a new one here. If linking works but completing a task or changing its category never reaches the issue, that token's Issues permission is still Read-only; upgrade it there.

Category colors

Due dates

A task's due chip turns yellow, then red, as its time runs down. The cut-offs are a share of the time between setting the due date and the due date itself, so a task due in three months and a task due in three days both turn at a fitting moment. An overdue task is always red. A task can still pick its own lead times when you set its date.
